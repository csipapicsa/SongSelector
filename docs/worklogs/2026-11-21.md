## Linux release (branch `feature/linux-release`, PR #52)

User: the app is good enough to release for Windows **and Linux**. Linux had no packaging yet (backlog item 3,
plan of 2026-11-20); Mixxx support (draft PR #42) is not part of this release ("current status").

- **First, the suite on Linux** (WSL worktree `~/ss-linux`, the existing venv): 331 passed, 4 failed on `main`.
- **Track keys.** `canonical_path` folded every path the Windows way, also on Linux (`/home/x/A.mp3` ->
  `\home\x\a.mp3`): two files differing only by case became one track. Changed before the first Linux release,
  because the key is stored with every analysis and layout; later it would have needed a migration. Rule: Windows
  paths (drive letter or a `\\server\share` network path) are folded on any system (they also come from Traktor/Rekordbox files and the
  tests' fixtures); other paths only `posixpath.normpath`. Traktor's NML reader (`native_path`) spells paths by the
  same rule; it built `\tmp\...` from Linux paths before, which the new keys exposed (8 more failures, one cause).
- **Data folder.** A frozen app kept its data next to the exe. An AppImage runs from a read-only mount at a new
  `/tmp/.mount_*` path each start, so on Linux the frozen app uses `$XDG_DATA_HOME/SongSelector`. Windows unchanged.
- Other gaps: `os.startfile` -> `QDesktopServices.openUrl`; `requirements.txt` with environment markers
  (`onnxruntime-directml` on Windows, `onnxruntime` 1.24.4 elsewhere, verified by a fresh venv in WSL); the analysis
  process gets `os.nice(10)` on Linux (Windows: below-normal class), where it runs on the CPU; `pyi_splash` is only
  imported when the bootloader shows a splash (`_PYI_SPLASH_IPC`), else it printed a traceback on Linux.
- **Tests made platform-independent**: `other_spelling()` (capitals on Windows, `/./` on Linux: POSIX keeps a
  leading `//`, so a doubled slash was not the same path), a native path for `track_name`, the 3D test checks that
  near dots are bigger rather than 1.5x (the depth spread of 24 fake tracks depends on the t-SNE numerics), and the
  Ctrl+click test lifts its dot to the compared track's z-tier (the fake tracks of one style overlap on Linux).
- **AppImage.** The spec builds one folder on Linux (no Tcl/Tk splash, no UPX). `scripts/build_linux.sh`: AppDir
  with `packaging/linux/songselector.desktop` and a new icon (`packaging/make_icon.py`, also the window icon),
  packed by appimagetool 1.9.1 with the static type-2 runtime 20251108, both pinned by GitHub's SHA-256 digests (the
  "continuous" builds change under us). The static runtime needs no libfuse2 on the user's system. 127 MB.
- **Verification.** `scripts/verify_release.sh` mirrors `verify_release.ps1`: the self-check inside the AppImage
  (clean `env -i`), then the real window under `xvfb-run`, found by title and closed with `WM_DELETE_WINDOW` by
  `scripts/x11_window.py` (ctypes on libX11, no window manager in Xvfb), expecting exit 0 and the settings saved.
  In WSL (Ubuntu 22.04, FUSE mount) with all seven real models: `embedding_process: ok, 3x2048 on CPU` (the
  analysis process, spawned by the frozen app inside the mount), `clap_models: ok, LAION CLAP 2x512, Microsoft CLAP
  2x1024 on CPU, text search ok`, tokenizers downloaded from Hugging Face. The window test needs Xvfb (not in WSL
  without sudo): CI runs it.
- **CI.** Tests on `windows-latest` and `ubuntu-22.04`. The ruleset requires a check named `test`, which a matrix
  renames to `test (os)`: a small `test` gate job passes only if both passed (or were skipped for docs), so the
  ruleset stays as it is. Release: `build-linux` on ubuntu-22.04 (oldest glibc on the runners), publish waits for
  both builds and writes one `SHA256SUMS.txt`.
- CI on PR #52: tests green on both systems; release dry run green for both builds. On the runner the AppImage
  mounted with FUSE and the window test passed on Xvfb (window found, closed with WM_DELETE_WINDOW, exit 0, settings
  saved). AppImage 137 MB. Merged.
