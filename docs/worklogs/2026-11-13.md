## Free-text search with CLAP: CPU cost first (branch `research/clap-cpu-benchmark`)

User idea: type a description, get the closest tracks (top 10) in a window, save prompts. Model family: CLAP. User
asked to compare LAION CLAP and Microsoft CLAP, light versions, and to measure CPU cost first (no CUDA assumed).

- Backlog item added (Product).
- Light versions chosen from the Hugging Face file listings: LAION `clap-htsat-unfused` (615 MB) and Microsoft CLAP
  2023 (690 MB; the 2022 weights are 2.3 GB). LAION `larger_clap_music` (776 MB) added as a music-trained reference.
- Environment: isolated venv `.research_cache/venv-clap` (msclap pins transformers < 5 and numpy < 2; the system Python
  is untouched). transformers 4.57 refuses `.bin` weights on torch < 2.6 (CVE-2025-32434), so the venv got CPU-only
  torch 2.7.1 (+ matching torchvision, else the system's torchvision 0.20 breaks the transformers import).
- `docs/research/experiments/clap/benchmark_cpu.py`: one process per (model, threads); load, memory, window time,
  text latency, ranking, 8 real tracks (45.6 min) decoded and fully embedded.
- Result (4 threads): LAION light 5.5 s per 6-minute track for every window (CNN14 on the CPU: 6.4 s), about 1.5 s with
  6 sampled windows (derived); query 31 ms; 1.6 GB peak. MS 2023: 7.2 s, query 121 ms, 2.4 GB peak. LAION music:
  11.3 s, 35 ms. 8 threads gain only 4–12 % (4 physical cores).
- Decision: CPU cost is acceptable; candidate LAION light. Next: retrieval quality on labelled styles, then ONNX.
  Note: `docs/research/text_search_clap.md`.

## Startup splash screen (branch `feature/startup-splash`)

User: double-clicking the app shows nothing for a few seconds; wants a loading image. Also asked whether startup
reads all embeddings.

- Measured first (on a copy of the library, 3,753 tracks): Python start → window ~3 s (imports 0.7 s, window 2.3 s:
  tables ~1.2 s, Traktor `collection.nml` ~1.1 s); the one-file exe took 7.6 s to its window, so ~4-5 s is the
  bootloader unpacking before any Python runs. **Embeddings are not read at startup** (analysis compares
  fingerprints; the map loads vectors only when opened), so that was not the delay.
- Two splash layers, same image (`src/songselector/ui/splash.png`, drawn by `packaging/make_splash.py` with Pillow):
  PyInstaller `Splash` in the spec (appears immediately, during unpacking) and a Qt `QSplashScreen` in `app.main` that
  takes over, closes the first and finishes when the window shows. Status text at the same spot in both
  (PyInstaller anchors text south-west; Qt `drawText` uses the baseline).
- PyInstaller's splash needs Tcl/Tk at build time; the local Python 3.11 has none (installed without it), GitHub's
  runners do. The spec checks `tcltk_info.available` (Splash itself raises SystemExit, which `except Exception` would
  not catch) and builds without it, with a warning.
- `launcher.py` closes the exe's splash in the embedding worker (`--multiprocessing-fork`) and in the self-check.
- Tests: `tests/test_splash.py`; the exe's self-check now checks the bundled image (`"splash": "ok"`).
- Backlog: multi-model embeddings (user's choice of models; CLAP), research question "does CLAP group by feel",
  startup numbers.

## Merges; CLAP models in the app, release 1.1.0 (branch `feature/clap-models`)

User: merge the open PRs, then "I want the app version which already handles these models. Go for it."

- Merged PR #12 (research) and #13 (splash; worklog conflict resolved by keeping both sections). The user's notebook
  with outputs, stashed during the branch switch, restored as an uncommitted change.
- **Step 1, ONNX export** (`scripts/export_clap_onnx.py`): every model takes raw audio; LAION's log-mel spectrogram is
  built into the graph (Hann-windowed DFT as two conv1d, reflect padding, Slaney mel, dB) and matches transformers'
  extractor to 8e-08. All exports are checked against PyTorch (1e-6 or better), text through the app's own
  `tokenize`. Fixed on the way: msclap HTSAT `int()` froze the batch size (cosine 0.62 at batch 3); transformers'
  vmap masks not traceable (switched to its non-vmap implementation); GPT-2 cache off. Research venv also needed
  `onnx` and NumPy pinned back to 1.26 (onnx pulled 2.5, which breaks numba).
- DirectML in the app's runtime: batch 4 fastest for CLAP (62 / 55 ms per window), batch 8 overflows the 4 GB card.
- **Step 2, app:** `core/embedding_models.py` (three model specs); `embeddings.py` generalised: `load_audio_rates`
  (one decode, resampled per model; CNN14's input bit-identical to before), `OnnxEmbedder`, a store per model
  (separate cache files: the CNN14 table has path_key as primary key, so no shared table without migrating 227 MB),
  `run_analysis` with all enabled models. Analysis menu: *Embedding models* (checkable, disabled with the missing
  file names when files are absent), *Similarity model* (map/matches/groups; `SimilarityMapWidget.set_store`),
  *Open models folder*.
- **Step 3, search window:** `core/text_search.py` (tokenize, TextEncoder, rank, process loop),
  `ui/text_search_worker.py` (process started on first query, stopped on close), `ui/text_search_dialog.py`
  (model choice, prompt, top N, saved prompts, double-click to select, add to playlist, drag to Traktor).
- `tokenizers` 0.23.3 added (pinned with its dependency tree for pip-audit); huggingface_hub/hf_xet/fsspec excluded
  from the exe, since `Tokenizer.from_file` never loads them (checked).
- Tests: `tests/test_clap_models.py` (definitions, multi-rate decode, one process filling three caches at their own
  rates with fakes, tokenizing, ranking, text process, search window, main window menus); a real-model test runs
  with `SONGSELECTOR_CLAP_MODELS` (both models: tone closer to "a pure sine tone" than to "speech"). Self-check in
  the exe: the text search process with the real tokenizers library.
- Version 1.1.0.
