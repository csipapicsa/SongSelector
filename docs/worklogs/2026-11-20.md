# 2026-11-20

## Linux under WSL: first run

- WSL 2 with WSLg (Windows 11) runs Linux GUI apps as normal Windows windows, with PulseAudio; no X server or
  desktop needed. Ubuntu 22.04 has Python 3.10, the project needs 3.11: `uv` (in `~/.local/bin`, no sudo) made a
  3.11 venv in `~/SongSelector` (cloned on the Linux filesystem; `/mnt/e` is slow from Linux).
- Dependencies: `requirements.txt` with `onnxruntime-directml` swapped for `onnxruntime` (DirectML wheels are
  Windows-only). Everything else installed as pinned. Qt's xcb plugin found all its libraries except
  `libpulse-mainloop-glib` (QtMultimedia only, not used by the app).
- The app started and closed cleanly (exit 0). Found: opening a folder (models) goes through `xdg-open`, which
  finds no file manager in WSL; `wslu` (`wslview`) or a Linux file manager fixes that on the WSL side.
- Linux portability gaps seen in the code: `os.startfile` in `main_window.on_item_double_clicked` (Windows-only),
  CPU priority lowering only on Windows (`embeddings.py`), Rekordbox / Traktor paths are Windows paths.

## Compact top bar, one Model box, free map panning (branch `feature/compact-top-bar`)

User feedback while testing in WSL: the map's *Own window* "doesn't make any sense", the model should be chosen next
to *Describe a sound* and drive the map too, several buttons are unneeded, the tempo slider takes too much room, and
the map cannot be moved freely (a hover card at the edge stays cut off).

- Removed from the UI: *Own window* (the button is kept off the toolbar so `set_map_detached` still works; a map
  left detached is no longer restored at startup, since there would be no way back but closing it), *Refresh*,
  *Load CSV* (methods kept: tests and the self-check use them), *Show all tracks* (Browser -> All Tracks does it),
  *Add Selected to Playlist* (moved into the List's right-click menu so it stays reachable besides dragging).
- **Master tempo:** a bold `QSpinBox` (`tempo_box`, 70-200, " BPM") at the start of the search row, user's choice
  of three placements. Keyboard tracking off (typing 128 applies once), and a 250 ms single-shot timer so a burst of
  arrow clicks rebuilds the List once (`apply_tempo`, was `update_tree_after_slider`). `bpm_slider` renamed
  everywhere, including `selfcheck.py` (the exe's self-check, which CI would only have hit at release).
- **One Model box** (`model_box`, was `description_model`), user's choice "all models": it shows and sets
  `Similarity model`; `set_similarity_model` also sets `Text search model` for a CLAP model and re-runs a description
  search on the List. With CNN14 (no text side) the description field is disabled with a hint; switching to CNN14
  keeps the shown results and says which model they came from. The map's own Model box (added this morning in PR
  #46) and its `model_requested` signal are gone.
- **Free panning:** a `QGraphicsView` only scrolls within its scene rect, which was the dots plus 5 %: at the fitted
  zoom there was almost no room, and zoomed out none. Now the map plus `PAN_ROOM` (3) times its size on every side;
  scroll bars off (they would always show), drag pans, *Fit* brings it back. Test: after Fit the view can be scrolled
  until no dot is visible, still moves zoomed out, and Fit centres the dots again.
- Checked the layout with a real render (`WA_DontShowOnScreen` + `grab()`; the offscreen platform has no fonts on
  Windows): two rows above the List instead of five.
- User idea for later, explicitly not now: single-key shortcuts (e.g. F = Fit); in the backlog.

## Map view options and a foldable top (branch `feature/map-view-options`)

User's list (screenshots of the map, its toolbar and the search rows; also in the untracked `docs/WP-2026-11-20.txt`):

- **Turn the 2D map (Shift+right-drag).** Done in the projection, like the 3D view's yaw/pitch, not with
  `QGraphicsView.rotate()`: one mechanism for both views, and everything that works on the projected positions
  (scene rect / panning room, *Fit*, box placement) needs no change. `_project` turns the scaled 2D points about the
  origin (`turned()`: clockwise on screen, y points down). `_place_dots` keeps the scene point in the
  middle of the view there (turns it by the same angle and `centerOn`), so the map turns about what is being looked
  at. Horizontal drag only (right: clockwise), `ROTATE_SPEED` as in 3D; setting `Map 2D turn` (radians). The view
  takes Shift+right-press before the scene, so on a dot it turns instead of selecting it and opening its menu; the
  context menu event that follows the right button (Windows: on release, Linux: on press) is swallowed.
- **Every detail on the map can be switched off, per place** ("there is no hard coded thing which cannot be
  changed"). The cover, *Artist - Title*, the key/BPM line, mix and similarity and the group were always shown; only
  the List columns could be chosen, once for the card and the panel. Now `details_html(key, place)` builds the hover
  (and compare) card, the selected track's label and the details panel from setting `Map details`
  (`{card|label|panel: [items]}`); *View → Map track details…* is a grid, a column per place. Mix and similarity has no
  box for the label and panel (the selected track has no mix with itself). Defaults = what was shown before; the old
  `Map hover fields` carries over (map items on + those columns) and is dropped when the dialog saves. Nothing chosen:
  no card, no label (ring and glow remain). The label became rich text so it can show columns and the cover too.
- **The cover could not be switched off on the hover card**: it is the *Cover art* row of that grid (per place, so
  the panel can keep its larger cover while the cards drop it).
- **Show/hide the selected track's details** above the closest matches: right-click anywhere beside the map (the
  details, the caption, even a match's row: the list ignores context menu events, so Qt passes them on to the panel)
  or *View → Selected track details*; setting `Map details panel`, the menu tick follows a signal. The details' own
  menu had *Copy* (selectable text); kept in the new menu, with *Choose track details…*.
- **The map's toolbar is the last row**, below the map and its status line.
- **The search rows can be folded away**, like the Playlist/Browser on the left: they are now the top of a vertical
  splitter (`search_splitter`), collapsible by dragging the line up or with *View → Search bars* (setting
  `Show search bars`, restored at start). The panel's vertical size policy is *Fixed*, so the splitter shows the rows
  whole or not at all and never stretches them.
- Tests (`MapViewOptionsTests`, `TurnTests`, cover per place in `MapCoverTests`): the turn by real mouse events on a
  dot (angle, clockwise, the middle stays, no selection, no menu, the context menu swallowed once), each item off in
  turn, nothing chosen, columns on the label, the carry-over and the dialog's save, the right-click on a match's row,
  the View menu tick, *Copy*, the folded rows after a restart. A first version of the panel test hung: the dialog
  signal is connected to the bound method at start, so patching `window.choose_map_details` later opened the real
  modal dialog; patching `MapDetailsDialog.exec_` fixed it.
- Layout checked with a real render (native platform, `WA_DontShowOnScreen`, `grab()`): toolbar at the bottom, rows
  folded, details hidden, map turned, the dialog's grid.
