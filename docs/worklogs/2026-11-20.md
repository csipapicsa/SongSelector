# 2026-11-20

## Linux under WSL: first run

- WSL 2 with WSLg (Windows 11) runs Linux GUI apps as normal Windows windows, with PulseAudio; no X server or
  desktop needed. Ubuntu 22.04 has Python 3.10, the project needs 3.11: `uv` (in `~/.local/bin`, no sudo) made a
  3.11 venv in `~/SongSelector` (cloned on the Linux filesystem; `/mnt/e` is slow from Linux).
- Dependencies: `requirements.txt` with `onnxruntime-directml` swapped for `onnxruntime` (DirectML wheels are
  Windows-only). Everything else installed as pinned. Qt's xcb plugin found all its libraries except
  `libpulse-mainloop-glib` (QtMultimedia only, not used by the app).
- The app started and closed cleanly (exit 0). Found: opening a folder (models) goes through `xdg-open`, which
  finds no file manager in WSL; `wslu` (`wslview`) or a Linux file manager fixes that on the WSL side.
- Linux portability gaps seen in the code: `os.startfile` in `main_window.on_item_double_clicked` (Windows-only),
  CPU priority lowering only on Windows (`embeddings.py`), Rekordbox / Traktor paths are Windows paths.

## Model files on Hugging Face (branch `feature/models-on-hf`)

- User logged in with a fine-grained write token (`hf auth login`, own terminal; huggingface_hub 2.4.0).
  User decisions: Microsoft CLAP is in the first upload; no quantized models (the int8 item is closed).
- One repo per model, created **private** so the files can be uploaded and the download tested before they go
  public: `csipapicsa/songselector-cnn14` (cc-by-4.0), `songselector-clap-laion` (apache-2.0, base
  `laion/clap-htsat-unfused`), `songselector-clap-ms` (ms-pl, base `microsoft/msclap`). Licence tags checked against
  the original repos' own metadata (msclap is `ms-pl`, LAION `apache-2.0`).
- Model cards live in `packaging/models/hf/<repo>/README.md` (versioned, reusable by a later upload workflow):
  files with sizes and SHA-256 (the `FILES` values), input/output names and shapes read from the ONNX files,
  source, citation, changes, licence. The Microsoft card states the app's tokenization (`' <|endoftext|>'` suffix,
  77 ids padded with 0), so the vectors can be reproduced outside the app. Apache / MS-PL texts uploaded as `LICENSE`.

- Upload: the 7 files of `dist\models` checked against `FILES` first (all match), then one `hf upload` per repo.
  Hugging Face reports the same sizes and LFS SHA-256 as `FILES`. Pinned commits: cnn14 `8ebf372b`, clap-laion
  `14bcb104`, clap-ms `73b59b59`.
- App: `HUGGING_FACE` (repo -> commit, files) and `URLS` (`resolve/<commit>/<file>`) replace the empty `BASE_URL`;
  `url(name, base_url)` keeps `Model download URL` as an override. The window always offers the download now and
  says where from; the "not distributed" branch is gone (the build link stays). Selfcheck fetches the tokenizers
  from Hugging Face with `SONGSELECTOR_VERIFY_DOWNLOAD=1`. Tests: every file has a 40-hex commit (a branch name
  would let a later push change what a version downloads), the override, the window's default.
- Tested against the private repos with the app's own `download()` (token sent to huggingface.co only, as an
  unredirected header): both tokenizers in full, and `clap-laion-audio.onnx` resumed from a `.part` 2 MB short;
  the first progress value was the `.part` size, so the Range header survives the redirect to the file storage.
- `scripts/publish_models.ps1` (GitHub release) replaced by `scripts/publish_models.py`: check against `FILES`,
  then one commit per repo with card, licence and files, printing the commits to pin.
