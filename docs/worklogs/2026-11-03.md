## Map and grouping for the listed tracks only (4.24.0)

Question from the user: does a genre-only set cluster better when refitted (yes: vectors are centred
on the set's mean and t-SNE spends its resolution inside the set), and the app could not do it -
Re-arrange map and the groups always used every analysed track.

- `build_map_data(..., only=keys)`: loads just those embeddings, centres the vectors on them, lays
  them out (2D, and 3D if shown) from scratch and stores nothing, so the library layout is intact.
- Map bar: **Only listed tracks** (checkable). On: snapshot of the List's visible rows -> new map data
  -> fit view; groups follow because they are computed from the map data. **Re-arrange map** in this
  mode snapshots the List again. Off: library map (stored layout) returns. A toggle during a running
  load queues one more load (`_again`).
- Status line says the map holds only the tracks listed when it was arranged, and how many listed
  tracks are not on it. Group summary: "of the N mapped tracks".
- Measured t-SNE time on random 4096-d vectors: 100 tracks 0.1 s, 200 0.3 s, 500 2.9 s (+0.1 s grouping).

## Research: can sound predict a track's rating / colour? (docs/research/)

User asked whether clustering could fill the ~1,300 missing ratings and ~1,700 missing colours.
Findings (details and numbers in `docs/research/rating_color_prediction.md`):
- It is prediction, not clustering. On CNN14 neither nearest neighbours nor logistic regression / a small
  neural net beat "always the most common value" by much (rating 37-39 % vs 37 %; colour 51-54 % vs 49 %).
  Window length, pooling and the genre tags / folder did not help either.
- Per colour (one against the rest, artist-grouped validation) colours 1 and 5 carry a signal (AUC 0.79 and
  0.84); ratings hardly (4-5 vs 1-3: AUC 0.61). Not enough to suggest values automatically.
- Literature: audio explains little of personal liking; music-trained embeddings (MERT, MAEST, Jukebox) do better
  on tagging/emotion but not proven for personal labels. No DJ-specific study found.
- Candidate models checked (licence, size): `docs/research/model_candidates.md`. Most are non-commercial
  (fine for a personal tool); MusiCNN 3 MB, OpenL3 and Discogs-EffNet 18 MB are the light ones.
- Built: `docs/research/` index, plan with validation rules (artist-grouped CV, 20 % locked test artists,
  bootstrap intervals, a shipping bar fixed in advance) and `experiments/rating_color/` (evaluate.py + common.py,
  `# %%` scripts). The CNN14 baseline result is saved in `experiments/results/`. Experiments run on a copy of the
  data in `.research_cache/` (git-ignored); the app and exe are untouched.
- Next (not done): re-rating test for the label noise ceiling; extract MusiCNN / OpenL3 / Discogs-EffNet vectors.

- Research tooling added (`docs/research/experiments/rating_color/`): `models.py` (numpy mel front ends + onnxruntime for
  MusiCNN, Discogs-EffNet, OpenL3; Essentia ONNX files in `.research_cache/models/`), `selfcheck.py` (spectrogram equals
  librosa to 5e-7; Discogs-EffNet names the right styles for known-genre tracks), `extract_vectors.py` (resumable, labelled
  tracks first in random order), `taste_sheets.py` (blind re-rating sheet and the "valid" yes/no sheet with scoring).
  MusiCNN fails to compile on DirectML with graph optimisation on (silent CPU fallback): optimisation off for that model.
  Genre-tag notes `e:4` / `h:3` (about 160 tracks) correlate only 0.12-0.13 with rating: not a hidden signal.
- Sheets for the user in `docs/research/sheets/` (README there): `rerate_2026-11-03.csv` (60 tracks, blind) and
  `valid_cnn14_2026-11-03.csv` (117 suggestions to mark yes/no; made with CNN14 for now).
- Extraction of the three small models over the library started in the background (about 8 s per track and worker).

- Result of the model comparison (800 tracks, same validation): CNN14, MusiCNN, Discogs-EffNet, OpenL3 are
  indistinguishable on rating (AUC 0.58-0.61) and on each colour, although Discogs-EffNet groups styles much better
  (86 % of 10 nearest share the style vs 71 % for CNN14). So the limit is the labels, not the embedding. Extraction
  stopped at 800 tracks (resumable). BPM / key / loudness predict almost nothing about rating (AUC 0.55); play
  history and cues help a little (0.66) but are missing for the unrated tracks (77 % never played).
  Large models (MAEST, MERT, CLAP) not tried: wait for the user's re-rating sheet, which gives the ceiling.

## 4.25.0: Rekordbox playlists in the Browser (direct read)

- The user chose to read `master.db` directly ("do not want to interact with Rekordbox, so it has to be automatic").
- `core/rekordbox_library.py`: `RekordboxLibrary` (same shape as `TraktorCollection`: `path`, `error`, `playlists`, `_load()`),
  `discover_library()` (Rekordbox settings `masterDbDirectory`, else `%APPDATA%\Pioneer\rekordbox\master.db`; env
  `TRAKTOR_REKORDBOX_LIBRARY` overrides, `none` disables, used by the tests), `signature()` (db + `-wal`), `database_key()`.
  Plain `sqlcipher3` and three queries; no pyrekordbox/SQLAlchemy. Reads a temporary copy, so a running Rekordbox is no problem.
- `ListBrowser`: generic `set_foreign_playlists(kind, ...)` for Traktor and Rekordbox (`FOREIGN_KINDS`); *Rekordbox Playlists*
  root hidden until a library is read. `saved_lists.py`: `_foreign_*`, `import_foreign_missing`, `copy_foreign_playlist`
  replace the Traktor-only versions. `CollectionWatcher` takes a `reader` and `signature` and has a `failed` signal (status bar).
- Menu *Import > Link Rekordbox library...*; setting `Rekordbox library`; `sqlcipher3-wheels==0.5.7` in requirements.txt,
  hidden import in the spec; the packaged self-check writes and reads a small encrypted library.
- Tests: `tests/test_rekordbox.py` (tree, order, deleted rows, streaming tracks, unchanged file not re-read, bad read keeps
  playlists, discovery) and one Browser test in `test_saved_lists.py`. 172 passed. On the real library the watcher read
  4,166 tracks and 5 playlists in 0.5 s.
- Fix found by the tests: `_load()` on a missing file returned silently (None == None); it now sets an error.
- Lesson (again): heredocs through this shell eat backslashes and turn `\b`, `\a`, `\r` into control characters; write
  text with backslashes using the Edit tool, and scan for `\x07 \x08` afterwards.
