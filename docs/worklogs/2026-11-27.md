# 2026-11-27

## Match on the map and in Advanced Search; G jump sharp with a sign (branch `feature/match-sizes-search-and-g-jump-signs`)

User asked for three things:

1. **Similarity map, 2D view: dot size follows the Match** while a *Describe a sound* search is shown (cosine
   similarity, -100 % to 100 %).
2. **Advanced Search: Match as a criterion.**
3. **G jump sharp gets a sign**: +3 when the move goes up three, -3 when it goes down.

Asked before coding (3): the move is three semitones, but on the Camelot wheel the same move goes the other way
(8A → 5A is Am → Cm: pitch +3, wheel -3). User chose **the pitch**: +3 = three semitones up.

Done:

- `core/harmonic.py`: `g_jump_sharp` split into `g_jump_sharp_up` (*+3 G jump sharp*, wheel step 9) and
  `g_jump_sharp_down` (*-3 G jump sharp*, wheel step 3), both weight 2, special, same teal edge colour (like +1 / -1
  mix share one). `RENAMED` + `current_names()` turn a saved `g_jump_sharp` (the map's `Map edges` setting) into both,
  so a user who had it ticked keeps both directions. `compatible_keys` now returns both targets; before, the two
  targets shared one dict key and one was lost.
- Map dot size (`ui/similarity_map.py`): `match_scales()` maps the Match of the dots shown to a scale of 0.6–2.2 ×
  `DOT_SIZE`, **relative to the shown range**, not to -100..100 %: CLAP scores sit in a narrow band (often 10–40 %),
  so the absolute scale would draw every dot nearly the same size. **Area** grows evenly with the score (diameter with
  the square root), since the eye compares dots by area. All equal / one score: normal size. The scale multiplies the
  3D depth scale, so it works in 3D too. Bigger dots sit slightly below smaller ones in their ring tier
  (`SMALL_ON_TOP`), so a big dot never hides a small one. The label and cards keep clear of a big dot (`dot_gap`, per
  box `gap` instead of the fixed `DOT_SIZE`). The status line names the range ("dot size: Match, 35 % (smallest) to
  41 % (largest)"). The Match comes from the List's Match column text ('31%'), which the map already receives.
- Advanced Search: `Match` added to `COMPLEX_SEARCH_COLUMNS` and `NUMERIC_COLUMNS`; the row offers only the number
  comparisons for it, with a percent hint. **A Match rule lets rows without a Match value through**
  (`matches_condition`): without that, *Match ≥ 30* with no description search would have emptied the List, and a
  smartlist with a Match rule (smartlists never carry scores) would always be empty.
