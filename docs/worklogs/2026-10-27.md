## 3. Own rating/color, tag editing, background embeddings (4.7.0)

Requests: Song Selector rating and color columns (editable, filterable); editing Artist/Title/Genre
written into the files (like Traktor); embeddings for every library track in the background,
saved in SQLite; GPU when available; distribution to-dos in the backlog; this worklog.

Decisions:
- *Rating - Song Selector* / *Color - Song Selector* stored in `library.sqlite` (schema 1 → 2,
  in-place migration). Only explicit edits change them, never imports, Refresh or Load CSV.
  Search: Advanced Search numeric + color names, search-bar `sscolor:`.
- Tag writing (`core/tag_writer.py`) reverses the old read-only rule for audio files, as the
  user asked: only Artist/Title/Genre, ID3 version kept, nothing changes if the write fails.
  `collection.nml` stays read-only.
- Embeddings: full resolution (2048 values / 5 s) kept, but **lossless float16 + zlib**:
  86.8 % of the values are 0, so ~50 KB per 6-minute track (~250 MB per 5k tracks)
  instead of 1.2 GB. The user found 2048 per 5 s too much: reducing (mean vectors, PCA)
  is cheap later, but discarding data now would mean hours of re-analysis.
  Separate file `embeddings.sqlite` (a cache) to keep `library.sqlite` (user data) small.
- Pipeline without PyTorch/librosa: soundfile + soxr + onnxruntime with the existing
  `cnn14.onnx`. Verified against the original: identical audio, embeddings within 1.1e-05.
- **Analysis runs in a separate process**, not a thread. Reason found while testing:
  onnxruntime crashes (access violation) when loaded after PyQt5 in the same process.
  The process also isolates decoder crashes and avoids GIL contention.
- Root cause of that crash: PyQt5-Qt5 ships MSVC runtime 14.26 (2020), the system has 14.50.
  It also broke the PyInstaller build. Fix: `scripts/update_qt_msvc_runtime.ps1` (run by
  setup, checked by build) replaces the old DLLs.
- Bug found and fixed: queuing all ~2,900 jobs at once filled the pipe; after a stop the app
  could not exit. Jobs now go 4 at a time; regression test added.
- GPU: GTX 1650 Ti, driver 555.97 (CUDA ≤ 12.5). onnxruntime-gpu 1.31 needs CUDA 13, so it
  fell back to the CPU; onnxruntime-gpu **1.22 (CUDA 12)** works, using the CUDA/cuDNN DLLs from
  the MusicFindBoundaries PyTorch install via `TRAKTOR_CUDA_DLL_DIR`. 0.6 s vs 5.5 s model time
  per track (batch 16). The exe stays on the CPU (CUDA would add more than 1 GB); GPU is optional
  from source (`requirements-gpu.txt`).
