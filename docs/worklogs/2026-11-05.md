## Skip lint / audit / test for documentation-only PRs (branch `ci/skip-tests-for-docs`)

- The user asked whether CI can skip tests when only docs change (PR #6 waited ~5 min for a Markdown edit).
- Not `paths-ignore`: with required checks, a workflow that never starts leaves the checks "Expected" forever and the
  PR can't merge. Instead a `changes` job classifies the PR's files (`git diff --name-only HEAD^1 HEAD` on the merge
  preview), and lint/audit/test have `if: needs.changes.outputs.code == 'true'`. Jobs skipped by a condition count as
  passed for required checks.
- Fail-safe: only `docs/`, `*.md`, `LICENSE` are documentation; anything else, or an empty diff, runs everything.
  Classifier tested locally on 9 cases (docs only, README, LICENSE, mixed, requirements, workflow, docs/research/*.py,
  empty). Push to main, schedule and manual runs always run everything. secret-scan always runs.
- `changes` must become a required check: if it failed, the dependent jobs would be skipped, i.e. "passed".
- Workflow YAML parsed and checked (jobs, needs, conditions, outputs) with a scratch PyYAML.

## CD: release workflow (branch `cd/release-workflow`)

- `release.yml`: a `v*.*.*` tag builds, verifies and publishes; PRs that touch the packaging run the same build as a dry run.
- Two jobs for least privilege: `build` (windows, `contents: read`) runs all third-party code (pip, PyInstaller);
  `publish` (ubuntu, `contents: write`, tags only) only downloads the verified artifact and runs `gh release create`.
- Gates in `build` for a tag: tag must equal `v` + `__version__` and the tagged commit must be an ancestor of
  origin/main (released code went through a PR). Tested locally: v1.0.0 ok, v1.0.1 rejected while the code says 1.0.0.
- CI reuses the developer scripts unchanged: `python -m venv .venv` then `setup.ps1` (skips venv creation when .venv
  exists; installs pins; replaces PyQt5's outdated MSVC runtime), `test.ps1 -m "not local_data"`, `build.ps1`,
  `verify_release.ps1`. Shell pwsh: Windows PowerShell 5.1 turns native stderr into terminating errors when output is
  redirected (the reason build.ps1 switches to Continue around PyInstaller).
- New `scripts/release_notes.ps1`: prints one version's CHANGELOG section; fails if missing/empty. Tested: 1.0.0 stops at
  the "# Pre-1.0 history" heading, old sections, Unreleased, missing version → error. Dry runs use Unreleased and fall
  back to the current version's section.
- Release assets: the exe, SHA256SUMS.txt; notes from the changelog. README release checklist rewritten.
- Unknown until the first run: whether verify_release's native-window stage works on a GitHub-hosted Windows runner.
- Result: the dry run passed on the first try (setup 35 s, tests 67 s, build 48 s, verify 21 s), so GitHub-hosted
  Windows runners do open real windows, and the packaged self-check (incl. the lint PR's selfcheck.py edits) passed
  inside the built exe. Merged as PR #8.
