## Lint gate (branch `lint/adopt-ruff`)

- ruff 0.17.3, pinned. Its *default* rule set in this version is broader than the classic E4/E7/E9/F (it reported B, PL,
  FURB, S... even with `--isolated`), so the rules are listed explicitly in `pyproject.toml`: E4, E7, E9, F, B, I, UP.
  B905 (zip strict=) ignored. Otherwise a ruff upgrade could turn CI red without a code change.
- 139 findings → 0: 98 safe automatic fixes (import order, unused imports, `Optional[X]` → `X | None`), 6 lambdas →
  defs (ruff's "unsafe" fix: only `__name__` changes), the rest by hand:
  - Real: `wait_for_map` defined twice in `SimilarityMapInteractionTests`; the second (weaker, ignores `_again`) silently
    replaced the first. Kept the stricter one. `config.py` docstring after the imports (not a docstring); a mid-file import.
  - `dtype == object` → `dtype.kind == 'O'` (E721 false positive for numpy dtypes; `is` would have been wrong).
  - `assertRaises(Exception)` → `soundfile.LibsndfileError`; unused `hover` in `_refresh`; B023 lambda bound with `name=name`
    (it runs inside `.map()` immediately, so not a live bug).
  - 13 one-line `for x: y` / `a; b` statements split. A regex attempt broke a string containing `color:`; ruff caught the
    syntax error at once, files restored and edited exactly.
- Verified: ruff clean; pytest 181 passed, 2 skipped (same as before). Import reordering checked: no file sets environment
  variables before imports. `selfcheck.run()` from source fails identically on unchanged main (it needs the frozen exe),
  so it is verified by the next exe build.
- CI: new `lint` job on ubuntu-latest (OS-independent, faster start), ruff version read from requirements-dev.txt,
  `--output-format=github` for inline PR annotations. Workflow-wide `permissions: contents: read`, concurrency (new PR
  pushes cancel outdated runs; main runs always finish), job timeouts.
