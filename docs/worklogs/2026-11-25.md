# 2026-11-25

## AllMusicCaps distillation, Phase 0: is a small student cheaper on the CPU? (branch `research/distill-phase0`)

Starting point: the user's distillation brief (`docs/research/AllMusicCaps_distillation_project - 2026-11-125.md`,
local) proposes training a small student that maps log-mel / MFCC features into AllMusicCaps' audio space, so CPU-only
users do not have to run the 296 MB OMAR-RQ audio model. Assessment before any training:

- On a GPU the teacher is already fast (~24 ms per window); the problem is the CPU (112-217 ms per window), where the
  app embeds every window: 4-8 s per 6-minute track.
- The 6-window sampling decided on 2026-11-22 is not in the app yet; it is the fair baseline for a student.
- Speed and quality are separate questions: speed needs no training (random weights run at the same speed), so it was
  measured first. Quality (Phase 1) does not need 100 freshly embedded tracks: the app's cache already holds 130,705
  teacher window vectors for 3,380 tracks.

Done:

- `docs/research/experiments/distill/`: `common.py` (paths, the app's decoder and windowing, a frozen snapshot of the
  teacher cache, as the research convention asks), `students.py` (4 students with the log-mel front end inside the
  network, exported to ONNX with the app's "audio" -> "embedding" contract, ONNX vs PyTorch cosine 1.000000),
  `benchmark_speed.py` (each model and thread count in a fresh process: wall time, CPU time, memory, on 10 library
  tracks with the app's decoder and session options), README with results and the Phase 1 plan, pinned
  `requirements.txt`.
- Research venv `.research_cache/venv-distill` (torch 2.8 CUDA, onnxruntime-directml 1.24.4 as in the app,
  MLflow 3.18), on E:.
- Results (`results/2026-11-25_distill_phase0_speed.json`), per 6-minute track: app today 5.87 s / 21.2 CPU-s;
  teacher with 6 windows 1.60 s / 4.2 CPU-s (4 threads); student `cnn4-64` with 6 windows 1.04 s / 1.04 CPU-s
  (1 thread). Decoding is 0.81 s of that, so against the 6-window teacher a student gains 1.5-2.7x in wall time but
  4x in CPU time, plus 296 -> 3 MB and ~315 MB less memory. Student size barely matters (0.94-1.04 s for all four);
  the ONNX log-mel front end (~27 ms per window) is most of it. Decision: go on with Phase 1.
