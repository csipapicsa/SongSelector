## AllMusicCaps distillation, Phase 0: is a small student cheaper on the CPU? (branch `research/distill-phase0`)

Starting point: the user's distillation brief (`docs/research/AllMusicCaps_distillation_project - 2026-11-125.md`,
local) proposes training a small student that maps log-mel / MFCC features into AllMusicCaps' audio space, so CPU-only
users do not have to run the 296 MB OMAR-RQ audio model. Assessment before any training:

- On a GPU the teacher is already fast (~24 ms per window); the problem is the CPU (112-217 ms per window), where the
  app embeds every window: 4-8 s per 6-minute track.
- The 6-window sampling decided on 2026-11-22 is not in the app yet; it is the fair baseline for a student.
- Speed and quality are separate questions: speed needs no training (random weights run at the same speed), so it was
  measured first. Quality (Phase 1) does not need 100 freshly embedded tracks: the app's cache already holds 130,705
  teacher window vectors for 3,380 tracks.

Done:

- `docs/research/experiments/distill/`: `common.py` (paths, the app's decoder and windowing, a frozen snapshot of the
  teacher cache, as the research convention asks), `students.py` (4 students with the log-mel front end inside the
  network, exported to ONNX with the app's "audio" -> "embedding" contract, ONNX vs PyTorch cosine 1.000000),
  `benchmark_speed.py` (each model and thread count in a fresh process: wall time, CPU time, memory, on 10 library
  tracks with the app's decoder and session options), README with results and the Phase 1 plan, pinned
  `requirements.txt`.
- Research venv `.research_cache/venv-distill` (torch 2.8 CUDA, onnxruntime-directml 1.24.4 as in the app,
  MLflow 3.18), on E:.
- Results (`results/2026-11-25_distill_phase0_speed.json`), per 6-minute track: app today 5.87 s / 21.2 CPU-s;
  teacher with 6 windows 1.60 s / 4.2 CPU-s (4 threads); student `cnn4-64` with 6 windows 1.04 s / 1.04 CPU-s
  (1 thread). Decoding is 0.81 s of that, so against the 6-window teacher a student gains 1.5-2.7x in wall time but
  4x in CPU time, plus 296 -> 3 MB and ~315 MB less memory. Student size barely matters (0.94-1.04 s for all four);
  the ONNX log-mel front end (~27 ms per window) is most of it. Decision: go on with Phase 1.

## AllMusicCaps distillation, Phase 1: training students (branch `research/distill-phase1`)

- MLflow wired in (the user knows MLflow already, so no hands-on setup step): local SQLite store in
  `.research_cache/distill/`, experiments `distill-speed` (Phase 0, parent run + a child per model and thread count,
  logged from the JSON) and `distill-train` (Phase 1). Notebook `phase1_eval.ipynb` reads both; the venv is
  registered as Jupyter kernel `venv-distill` (VS Code did not list a venv inside `.research_cache`).
- `prepare_data.py`: artist-aware split from the snapshot: test = the 1,272 genre-test tracks, val = the 608 other
  tracks by test artists (artist-disjoint from training), train = the other 1,500 (up to 16 windows each). Log-mels
  computed by the students' own front end on the GPU, float16 cache (4.5 GB, 35,200 windows, 19 min, no track
  skipped). Checked first: fresh teacher inference on cached windows = cached targets (cosine 1.00000).
- `train.py`: 1 - cosine loss, AdamW 3e-4, batch 32, at most 10 epochs (user's choice), patience 3; ONNX export of
  the best epoch. fp16 mixed precision gave NaN from step 0 on the GTX 1650 Ti (and was slower), so fp32.
- `evaluate.py`: fidelity (window/track cosine, top-10 overlap) and the genre-AP test of allmusiccaps.ipynb;
  reference runs, paired bootstrap, export to `results/2026-11-25_distill_phase1.json`.
- Results (test): teacher 6 windows 0.285 genre AP, LAION 0.197; `cnn4-small-64` (0.23 M params, 1 MB) 0.300,
  `cnn4-64` 0.296, both within noise of the teacher (bootstrap intervals include 0) and ~+0.10 over LAION;
  `mfcc40-mlp` 0.208 (= LAION). The mean vector alone scores 0.71 window cosine, so raw cosine flatters; top-10
  overlap (closest matches) is only 0.17-0.19 for the CNNs. Learning curve: genre AP flat from ~1,000 tracks,
  fidelity still rising slowly. PR #78.
- Free-text queries (user's question: long, complex queries?): `evaluate.py --queries`, 59 queries
  (`docs/research/allmusiccaps_prompts.md`, now committed, plus the brief's 5 long descriptions). Students' rankings
  of the test tracks vs the teacher's: Spearman 0.74-0.75, top-50 overlap 0.37-0.39, top-10 0.18-0.21; LAION vs
  the teacher only 0.18 / 0.13 / 0.08. Long descriptions hold up as well as short ones (Spearman 0.79). The order
  agrees; the exact top 10 mostly differs.
