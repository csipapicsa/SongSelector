## 1. Playlist columns, map highlight, playlist marks, keyless matches (4.15.0)

Requests (from the user's `docs/TODO.txt` and chat): playlist column widths cannot be changed; make a
clicked closest match much more visible on the map (glow) and show its edges pale (~50 %); italic for
matches already on the playlist; recommendations seem to be missing, probably tracks Traktor has not
analysed, which should still be listed because the embedding carries the sound.

- **Playlist columns:** every playlist column was `QHeaderView.Stretch`, which blocks resizing by
  hand. Now `Interactive`. Second bug found on the way: widths were saved as *Column sizes left* but
  read as *Column Sizes left*, so they were never restored. Test: resize, restart, width kept.
- **Clicked match:** an uncommitted change from the last session had made a single click do nothing
  (double-click selects). The new request says the click highlight is wanted, so the click preview
  is back and stronger; double-click = select is kept (adding to the playlist is by dragging).
  Highlight: a pulsing radial-gradient halo (`QVariantAnimation` on its scale) plus a thick ring.
  Colour first orange, changed to magenta after looking at the user's screenshot: most dots there
  are orange/yellow, and no Traktor colour is magenta. Checked on a rendered screenshot.
- **Pale edges:** `_edge_sources` lists which tracks edges start from: the clicked match at alpha 85,
  then the selected track at 170 (on top). In "edges between all visible tracks" mode nothing extra
  is drawn (those edges are there already). Rebuilding the match list clears the highlight.
- **Italic:** the main window gives the map `playlist_keys`; matching rows are italic with a tooltip.
  The list is rebuilt after each playlist change (`filter_items` → `_refresh_map`).
- **Missing recommendations:** cause confirmed in code: the closest matches already include tracks
  without a Traktor key, but *harmonic only* dropped them (`mix_type` is `None` for "Unknown"), and a
  selected track without a key got an empty list. They are now kept with Mix *no key* (grey).
  Not changed: an Advanced Search BPM range also excludes tracks whose BPM is "Unknown"; that is an
  explicit filter.
- **Clustering** (user, mid-session): several lightweight unsupervised methods, chosen in settings,
  to explore why the map is one big blob. Not started; plan with three numpy-only candidates
  (k-means on PCA, kNN-graph communities, density clustering on the 2D map) in `docs/BACKLOG.md`,
  next to the 3D view item.
