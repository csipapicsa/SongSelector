## 2. Fewer graded edges, white glow, unsupervised groups (4.16.0)

Requests (with a screenshot: hundreds of white same-rating lines from one track): reduce the lines
and make them more transparent the weaker the connection; the selected track gets lost among them,
so it should glow too (white); try about three lightweight clustering methods, chosen in settings,
because the map looks like one blob although some groups are expected.

- **Edges:** "strength" = cosine similarity of the two tracks' full vectors (the same measure as
  the closest matches). Per source track only the N most similar partners are kept (spin box *to the
  N most similar*, default 20); opacity in 6 steps from 15 % (weakest of the layer) to full. This also
  closes the backlog item "edges only to the N closest matches".
- **Glow:** the halo became a `Halo` item class; white for the selected track, magenta for a clicked
  match. Hidden when the track is filtered out.
- **Groups** (`core/clustering.py`, numpy only): spherical k-means; Louvain communities on the
  10-nearest-neighbour graph; DBSCAN on the 2D map positions. Chosen in a *Groups* row on the map
  (a combo box, not a dialog: the user wants to play with it); one parameter each, remembered per
  method. Runs in a thread, newer requests win.
- **Measured on a copy of the user's data** (3,489 analysed tracks; `dist/` copied to the scratchpad,
  the live files untouched): each method ~1 s. Against genre or folder labels the groups looked no
  better than one group (0.30 → 0.32), but those labels are noisy (30 % no genre, a mixed "SELECTOR"
  folder). With a cleaner style label (DnB 1,262 / breaks 1,057 / house 380, from genre + folder):
  10-NN agreement 0.81 (chance 0.39); group purity k-means 0.75-0.77, communities 0.75-0.77, map
  density 0.83 (one group: 0.47). DnB forms clean groups, breaks and house mix. So the "blob" is
  mostly the 2D picture: the vectors do carry style.
- Map density at first gave 69 groups, many of 8-15 tracks, which became light grey beyond the
  palette and looked like "no group". Clumps under 1 % of the tracks now count as no group, and the
  default "dense %" is 60: 17 groups, 21 % ungrouped. Checked on rendered screenshots of the real map
  (edges, all three methods).

Verification: 130 tests + 192 table subtests (1 skipped: needs the real model); exe 4.16.0 passes
release verification (embedding step skipped again: no model path set).
