## 1. Playlist gaps, track counts, star ratings, more closest matches with chosen columns (4.17.0)

Requests (chat, two screenshots): the playlist shows empty columns without names; show how many
tracks are selected and, after filtering, how many the List view shows; choose the columns of the
closest-matches list on the map; ratings as stars instead of integers; list more closest matches,
not only the top 15.

- **Playlist gaps:** reproduced on a copy of the user's settings and library (`dist/` copied to the
  scratchpad, live files untouched) by printing `sectionPosition` per column: every hidden column
  had size 0 but still took 104 px, e.g. Camelot started at 382 px after Title ended at 70 px.
  Cause: since 4.15.0 `setSectionResizeMode(Interactive)` runs *after* `setColumnHidden`, and Qt
  then keeps the hidden sections' old width. Fixed by setting the mode first. The library list never
  set a mode, so it was not affected. Regression test: hidden columns between Title and Camelot,
  Camelot starts where Title ends.
- **Counts:** a label in the tab bar corner (*1,234 of 3,651 tracks, 3 selected*) and one under the
  playlist (*28 tracks, 2 selected*). Selected rows hidden by a search are not counted. Updated
  from the trees' selection and row signals through a 0 ms single-shot timer, because loading the
  library inserts thousands of rows one by one; `filter_items` also restarts it (hiding rows emits
  no model signal).
- **Stars:** `StarRatingDelegate` only changes the displayed text; the cell keeps the number, so the
  numeric sort, the text search ("5") and Advanced Search (`at least 4`) are unchanged. 0 is
  Traktor's "unrated" and stays blank (also left out of the map details, like colour 0).
- **Closest matches:** count spin box *List the N closest* (default 50, 5-2,000, saved as
  `Map match count`). Only the 15 most similar get a cyan ring on the map, otherwise 50+ rings
  cover it. Columns: Similarity, Mix, then all library columns (`MATCH_COLUMNS`, so Artist/Title
  keep indices 2/3); right-click the header to toggle, saved as `Map match columns`. Colour columns
  use the dot delegate, ratings the star delegate; numeric columns sort as numbers.

Verification: 135 tests + 192 table subtests (1 skipped: needs the real model); exe 4.17.0 passes
release verification (embedding step skipped: no model path set). Rendered
screenshots of the real data (offscreen, `QT_QPA_FONTDIR=C:/Windows/Fonts`): playlist without gaps
and with stars, both counts, map panel with 50 matches.

## 2. Compare with Ctrl+click, hover cards, colour dots (4.18.0)

Requests (chat, screenshot of the details box with "Color 2"): show the colour, not the integer;
Ctrl+click on a node should not select it but show its connection (similarity) to the base track
and its details in a pop-up, the base staying selected; show the harmonic mix (perfect mix, ...)
and the similarity score there too; use the colour codes; the yellow tooltip looks like Windows 95.

- **Ctrl+click** (`DotItem.mousePressEvent`) calls `compare(key)`, which reuses the existing
  preview (magenta glow and ring, pale edges) and adds: a dashed line base → track in the mix's
  edge colour (magenta when there is no harmonic mix; drawn even with all edge types off), and a
  pinned card. The match row is selected in the list when the track is among the matches. Ctrl+click
  on the same dot ends it; without a selection Ctrl+click simply selects. A click on a closest match
  goes through the same preview, so it gets the card too.
- **Cards** (`Card`: rounded `QGraphicsPathItem` + `QGraphicsTextItem` child, ignores zoom, lets
  clicks and hover through) replace the dot tooltips: artist - title, key/BPM now, mix + similarity
  to the selected track (`relation()`: cosine of the unit vectors, the same number as the list),
  the hover fields, the group. Opaque, because the hover and the pinned card can overlap (seen on a
  rendered screenshot of the real map with 238 alpha).
- **Colours:** `field_html` renders Traktor / Song Selector colour numbers as a coloured ● and the
  name, in the details box and the cards.
- **Yellow tooltips:** the dark palette already had a dark `ToolTipBase`, but on Windows `QToolTip`
  keeps its own platform palette. `apply_theme` now passes the palette to `QToolTip.setPalette`;
  the light theme gets a white tooltip. No application style sheet (it would wrap every widget in
  the style-sheet style).

## 3. Traktor background sync, sort freeze, curved edges, 3D view (4.19.0)

Questions and requests (chat): is anything syncing when a track changes in Traktor (tempo,
colour, rating)? Answer: no; the collection was only read on import, and at start / Refresh /
Load CSV only to fill *empty* ratings. Then: a low-priority background sync with batch updates;
curved edges ("straight lines are not appealing"); a 2D / 3D option with a well-known rotate
combination; and "selecting a column in the List view freezes the app".

- **Sync** (`core/traktor_sync.py`, `ui/traktor_watcher.py`):
  - `CollectionWatcher`: `QFileSystemWatcher` on the NML *and* its folder (Traktor replaces the
    file, which drops a file watch), a 60 s stat poll as fallback, a 3 s settle time (the file
    must be unchanged before it is read; a half-written NML does not parse), a first check 5 s
    after start. The parse runs in a daemon thread at `THREAD_PRIORITY_LOWEST`; the result comes
    back as one `TraktorCollection` and is applied in one batch (one library save, rows updated in
    place, one `filter_items`). An unreadable version is not retried until the file changes again.
  - Rule: first tried "Traktor always wins where it has a value". That broke the existing test
    *imported tag rating takes precedence over collection rating*, i.e. it would overwrite tag
    ratings/keys with stale Traktor values. Final rule: the app stores each track's Traktor values
    at the last sync (`traktor_seen` in `library.sqlite`); only fields Traktor changed since then
    are applied (also a cleared colour or rating; a vanished key/BPM analysis is not). First sight
    of a track: Traktor's colour (as an import does), key/BPM/rating fill empty values only.
  - Dry run on a copy of the user's library with the real `E:\DJ\TRAKTOR\collection.nml` (read
    only): 13,353 collection entries, parse 0.5 s, diff 0.06 s; first sync: 17 tracks, all colour
    (e.g. *Dancehall Thrilla* 6 → 3); second sync without a Traktor change: 0.
  - Known limit: *Refresh* / *Load CSV* rebuild from the CSV; imported tracks keep synced values
    (their saved imports are updated), CSV-only rows get them back only on the next Traktor change.
- **Sort freeze:** reproduced with the real library in an on-screen window: a header click took
  14.5 s with one row selected, 18.5 s with all selected, 0.08 s with none. Profile: 13.9 s in
  `takeTopLevelItem` — the old sort took all 3,651 rows out and re-added them; with a current
  item Qt re-laid out the view on every removal (60 delegate size hints per row). Now rows are
  `TrackItem`s whose `__lt__` uses `track_sort_key` (same order as before: numbers numeric,
  Camelot by number then letter, blanks/Unknown last, text now case-insensitive), and Qt sorts in
  place: 0.14 s with a selection. Also `setUniformRowHeights(True)`. Refresh / Load CSV no longer
  re-call the sort (that toggled the order); `populate_tree` keeps it.
- **Curved edges:** quadratic arcs, control point 18 % of the length beside the middle, always to
  the same side of the direction source → target, so a track's edges fan out. *Edges → Curved
  lines* (default on). Checked on zoomed renders of the real map.
- **3D view:** `tsne_layout(dims=3)` and `place_new` work in any dimension; 3D positions cached in
  `map_layout_3d` (embeddings.sqlite). No OpenGL dependency: the 3D cloud is rotated (yaw, pitch)
  and projected with mild perspective onto the same `QGraphicsScene`, so dots, rings, glows,
  cards, edges and Ctrl+click compare all keep working. Depth: far dots fade to 35 % and lie below
  near ones within their ring tier. Shift+drag rotates (handled in `MapView` before the scene, so
  it never selects); moves are coalesced with a 0 ms timer; angles saved. Edges are computed once
  and only redrawn while turning. Real data: first 3D t-SNE 198 s for 3,534 tracks (with the test
  suite running alongside), one rotation step 27 ms. Grouping "Map density" still uses 2D.

Verification: 146 tests + 192 table subtests (1 skipped: needs the real model), new tests for the
sync rules, the watcher (reads at start, re-reads after a save, not for an unchanged file), the
window batch update, curved/straight edges, 3D layout and Shift+drag. Rendered screenshots of the
real map in 2D and 3D. Exe 4.19.0 passes release verification (embedding step skipped: no model path set).
